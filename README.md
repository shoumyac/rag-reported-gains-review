# Do reported gains in retrieval-augmented generation survive scrutiny?

A pre-registered systematic review, meta-analysis and evaluation-validity audit of retrieval-augmented generation (RAG) research.

**Authors:** Anmita Das, Shoumya Chowdhury

**Registered protocol (OSF):** https://doi.org/10.17605/OSF.IO/XGPCZ (public, registered 1 November 2026 Sydney time)

> Status: protocol registered, search not yet run. No results exist yet. Every number in the eventual paper will be generated by script from the data in this repository.

## What we are doing

Many RAG papers report that a new method beats a baseline. We pool those within-paper improvements, test which design and evaluation choices explain the variation, audit how completely studies report what is needed to reproduce them, and stress-test published conclusions by re-running a pre-specified sample of methods under several metrics and LLM judges, with human labels on a sample.

We never rank methods across papers, because scores from different retrievers, generators and corpora are not comparable. Only within-paper contrasts are pooled.

### Research questions (as registered)

1. **RQ1.** Across studies that report a RAG method and a baseline on the same benchmark, what is the pooled reported improvement (in percentage points) and how much does it vary between studies?
2. **RQ2.** How much of that variation is explained by design and evaluation choices (baseline strength, retriever, generator, benchmark, metric, judge, language, year, venue type, code availability)?
3. **RQ3.** What share of studies report what is needed to reproduce and statistically compare their results, and do less transparent or smaller studies report larger gains?
4. **S1.** What share of RAG studies that use automated metrics or LLM judges validated them against human judgement?
5. **S2 (claim stress test).** For a pre-specified sample of methods re-run under a common setup, do reported gains replicate, and do conclusions change under different metrics and judges?

The registration on OSF is the authoritative text. If this repository and the registration ever disagree, the registration wins, and the difference is recorded in `protocol/deviations_log.md`.

## Integrity controls

- **No unverified citations.** References come only from OpenAlex, Crossref or DataCite metadata. `tools/check_citations.py` resolves every DOI in `references.bib` and compares titles. CI fails if one does not resolve.
- **Numbers by script.** The paper's numbers are generated from the frozen dataset; none are typed by hand.
- **Provenance for every extracted value.** Source file hash, page, table or figure, and a short quoted span.
- **Two independent LLM extractions** from different model families, with human verification of the primary outcome values.
- **Frozen protocol.** Changes after registration are logged in `protocol/deviations_log.md`.
- **Second implementation.** The main model is run in R and Python and must agree within a stated tolerance.
- **Own papers flagged.** Studies by the review team are flagged, screened and verified by an independent annotator, and excluded in a sensitivity analysis.

## Reproducing the search

```bash
cp .env.example .env        # then put your own OpenAlex key in .env (never commit it)
python search/oa_search.py count
python search/oa_search.py harvest --out data/raw/openalex   # frozen run is planned for 30 Nov 2026
```

The harvest saves the request URL (without the key), the time, the hit count and a SHA-256 hash for every raw response page.
